# پلنوما (Plannuma) — پروژهٔ کامل

بک‌اند **Django** (بدون DRF؛ ویوهای JSON بومی) + فرانت **Next.js 14 (App Router, TypeScript)**.

## امکانات
**سایت عمومی:** صفحهٔ معرفی (با قیمت‌های واقعی از سرور)، مقالات (بلاگ)، قوانین، حریم خصوصی، تماس، فرم مشاوره سه‌مرحله‌ای، sitemap و robots و تصویر اشتراک‌گذاری، فونت وزیرمتن داخلی (بدون گوگل).

**داشبورد:** کارها (ویرایش و انتقال به روز دیگر)، هبیت ترکر (روزهای مشخص هفته، یادآوری با اعلان، قالب‌های آماده)، کارهای تکراری، تایم‌باکس (ویرایش بلوک)، یادداشت، خواب، آب، تحلیل (هفته/۳۰/۹۰ و **سال**، مقایسهٔ هفته‌ها و بهترین روز هفته)، خلاصهٔ هفته، راهنمای اولین ورود، بنر تمدید اشتراک، حساب کاربری (تغییر رمز، حذف حساب، اعلان‌ها، تم رنگی، پشتیبان‌گیری JSON و وارد کردن JSON/CSV)، خروجی CSV، کپی هفتهٔ قبل، نصب‌پذیری PWA و حالت آفلاین ساده، گفتگوی پشتیبانی، تم روشن/تیره/سیستم، واکنش‌گرا برای موبایل.

**نسخهٔ رایگان و پرو:** رایگان = ۳ کار در روز، ۳ عادت فعال، ۱ کار تکراری، تحلیل تا ۹۰ روز. پرو = بدون این سقف‌ها + تحلیل سالانه + مقایسهٔ هفته‌ها + بهترین روز هفته + تم‌های رنگی + گزارش هفتگی خودکار. (سقف‌ها در `FREE_LIMITS` فایل settings تنظیم می‌شود و همه روی سرور اعمال می‌شوند.)

**پرداخت:** کارت‌به‌کارت با **مبلغ یکتا** (عدد کوچک اضافه‌شده برای تطبیق آسان)، **کد تخفیف**، مهلت ۲۴ ساعته، آپلود رسید، تأیید/رد ادمین (با پیام‌های آماده) و نمایش روزهای مانده.

**پنل ادمین:** صفحهٔ آمار (ثبت‌نام، کاربران فعال، پرو، درآمد، بازگشت ۷ و ۳۰ روزه، رسیدها و گفتگوهای منتظر)، بررسی رسید با رد آماده، کد تخفیف، درخواست‌های مشاوره، پاسخ‌های آماده و اطلاعات کاربر کنار چت، رمز موقت برای بازیابی رمز، ثبت لاگ تأیید/رد، **اعلان تلگرام/وب‌هوک** برای رسید، پیام پشتیبانی و مشاوره جدید.

**عملیات:** دستورهای `backup`، `send_reminders`، `weekly_report`، `generate_vapid`؛ پشتیبانی Redis (`REDIS_URL`) و Sentry (`SENTRY_DSN`) با تنظیم متغیر محیطی؛ لاگ؛ تست‌های بیشتر.

> **وضعیت تست:** نسخهٔ پایه روی سیستم شما اجرا و تأیید شده است. بخش‌های جدید این نسخه در محیطی ساخته شد که اینترنت و بستهٔ Django/Next نداشت؛ پس **اجرا نشده‌اند**. فقط بررسی‌های زیر انجام شد: کامپایل همهٔ فایل‌های پایتون، بررسی نحو و نوع (با تایپ‌های ساختگی) همهٔ فایل‌های TypeScript. اولین اجرا ممکن است نیاز به رفع اشکالات کوچک داشته باشد. `python manage.py test` را اجرا کنید (تست‌ها آمده‌اند ولی اجرا نشده‌اند).

## اجرا (محلی)
```bash
# ۱) بک‌اند
cd backend
python -m venv .venv && source .venv/bin/activate      # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env            # شمارهٔ کارت و قیمت‌ها را اینجا بگذارید
python manage.py makemigrations core
python manage.py migrate
python manage.py createsuperuser                        # حساب ادمین
python manage.py runserver                              # http://127.0.0.1:8000

# ۲) فرانت (ترمینال دوم)
cd frontend
cp .env.example .env.local
npm install
npm run dev                                             # http://localhost:3000
```
- سایت: `http://localhost:3000` — پنل ادمین: `http://127.0.0.1:8000/admin/`
- بعد از اولین اجرا: `npm run typecheck` را بزنید و خطاها را رفع کنید، سپس دو خط `ignoreBuildErrors` و `ignoreDuringBuilds` را از `next.config.js` حذف کنید.

## گردش‌کار ادمین
1. **پرداخت‌ها** (`/admin/core/payment/`): فیلتر «در انتظار بررسی» ← رسید را ببینید ← ردیف را انتخاب کنید ← عملیات **«تأیید پرداخت و فعال‌سازی پرو»** (یا «رد رسید»). پیام خودکار در گفتگوی پشتیبانی کاربر ثبت می‌شود. تمدید به انتهای اشتراک فعلی اضافه می‌شود.
2. **پشتیبانی** (`/admin/core/supportthread/`): گفتگوی کاربر را باز کنید، در ردیف خالی انتهای صفحه متن را بنویسید و ذخیره کنید (هر پیام جدید از طرف پشتیبان ثبت می‌شود).
3. **کاربران** (`/admin/auth/user/`): ستون پلن + عملیات «فعال‌سازی پرو ۳۰ روزه / بازگشت به رایگان».

## معماری و امنیت
- Next همهٔ `/api/*` را به Django پروکسی می‌کند (rewrites) تا کوکی هم‌مبدأ بماند و CORS لازم نباشد.
- احراز هویت: توکن تصادفی (فقط **هش SHA-256** در دیتابیس) در کوکی `HttpOnly; SameSite=Lax; Secure` (در تولید).
- محافظ CSRF: هر درخواست تغییردهنده باید هدر `X-Requested-With: plannuma` داشته باشد (سایت‌های دیگر نمی‌توانند آن را بفرستند).
- محدودیت تلاش: ورود (۸ بار/۱۵ دقیقه)، ثبت‌نام، آپلود رسید، پیام پشتیبانی.
- رسیدها: اعتبارسنجی نوع واقعی فایل (magic bytes، فقط JPG/PNG/WEBP، ≤ ۵MB)، نام تصادفی، ذخیره در `private_media/` (عمومی نیست) و فقط برای staff در `/admin-files/receipt/<id>`.
- رمزها با هشِ پیش‌فرض Django؛ حداقل ۸ نویسه و رد رمزهای رایج/عددی.

## استقرار (خلاصه)
1. `DJANGO_DEBUG=0`، `DJANGO_SECRET_KEY` قوی، `DJANGO_ALLOWED_HOSTS`، `DJANGO_CSRF_TRUSTED_ORIGINS=https://دامنه`.
2. `python manage.py collectstatic` و اجرا با `gunicorn config.wsgi` (WhiteNoise فایل‌های استاتیک ادمین را سرو می‌کند).
3. Next: `npm run build && npm start` با `BACKEND_URL` درست. پیشنهاد: پشت nginx مسیرهای `/api`، `/admin`، `/admin-files`، `/static` را مستقیم به Django و بقیه را به Next بدهید (برای آپلود رسید هم مطمئن‌تر است). HTTPS الزامی است.
4. کش پیش‌فرض (LocMem) برای محدودیت تلاش فقط در یک پردازه کار می‌کند؛ با چند worker از Redis استفاده کنید (`CACHES`).
5. از `db.sqlite3` (یا Postgres) و پوشهٔ `private_media/` به‌طور منظم نسخهٔ پشتیبان بگیرید.

## نکته‌های مهم این نسخه
- متن «قوانین» و «حریم خصوصی» نمونه‌اند؛ قبل از انتشار آن‌ها (به‌ویژه بازگشت وجه و نگهداری داده) را با نیاز کسب‌وکار و مشاور حقوقی بررسی کنید.
- اعلان وب روی آیفون فقط بعد از «افزودن به صفحهٔ اصلی» کار می‌کند و به HTTPS نیاز دارد.
- «امروز» بر اساس منطقهٔ زمانی `Asia/Tehran` است (`NEXT_PUBLIC_TZ` و `TIME_ZONE` باید یکی باشند).
- معیار بازگشت در آمار ادمین از زمان به‌روزرسانی ثبت می‌شود و برای کاربران قدیمی کمتر از واقع است.
- با حذف حساب، رسیدهای کاربر هم پاک می‌شود؛ اگر برای حسابداری لازم است نگه‌داشته شود، قبل از حذف از آن‌ها نسخه بگیرید.

## هنوز ساخته نشده
قابلیت‌های بعدی پرو (همگام‌سازی پیشرفته، هدف‌گذاری، قالب‌های بیشتر…)، پرداخت آنلاین (درگاه)، حالت آفلاین کامل با ذخیرهٔ محلی داده، بازیابی رمز خودکار (فعلاً با رمز موقت ادمین).
