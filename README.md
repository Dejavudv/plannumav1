# پلنوما (Plannuma) — پروژهٔ کامل

بک‌اند **Django** (بدون DRF؛ ویوهای JSON بومی) + فرانت **Next.js 14 (App Router, TypeScript)**.

## امکانات
- سایت معرفی (لندینگ)، ثبت‌نام و ورود با **نام کاربری و رمز**؛ ورود **ماندگار** (توکن در کوکی HttpOnly یک‌ساله)
- داشبورد: کارها، هبیت ترکر (روزهای مشخص هفته)، تایم‌باکس، یادداشت روز، خواب، آب، تحلیل نموداری، خلاصه هفته
- نسخهٔ رایگان با محدودیت **۳ کار در هر روز** و **۳ عادت فعال** (روی **سرور** اعمال می‌شود)
- منو: خروجی CSV (هفته/ماه/فصل/کل)، کپی برنامهٔ هفتهٔ قبل، پشتیبانی، ارتقا به پرو، تم روشن/تیره/سیستم، خروج
- ارتقا به پرو: **کارت‌به‌کارت** ← دکمهٔ کپی شمارهٔ کارت ← آپلود عکس رسید ← بررسی و فعال‌سازی توسط ادمین
- گفتگوی آنلاین با پشتیبانی داخل سایت (پاسخ از پنل ادمین)
- پنل ادمین Django (فارسی): کاربران و اشتراک، پرداخت‌ها (نمایش رسید + تأیید/رد)، گفتگوهای پشتیبانی
- دیتابیس: SQLite (پیش‌فرض) یا PostgreSQL
- حالت تیره بازطراحی شد (سطوح روشن‌تر و کنتراست بهتر)

> **وضعیت تست:** این پروژه در محیطی ساخته شد که اینترنت و بستهٔ Django/Next نداشت؛ بنابراین **اجرا نشده**. فقط بررسی‌های زیر انجام شد: کامپایل همهٔ فایل‌های پایتون، بررسی نحو و نوع (با تایپ‌های ساختگی) همهٔ فایل‌های TypeScript. اولین اجرا ممکن است نیاز به رفع اشکالات کوچک داشته باشد. `python manage.py test` را اجرا کنید (تست‌ها آمده‌اند ولی اجرا نشده‌اند).

## اجرا (محلی)
```bash
# ۱) بک‌اند
cd backend
python -m venv .venv && source .venv/bin/activate      # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env            # شمارهٔ کارت و قیمت‌ها را اینجا بگذارید
python manage.py makemigrations core
python manage.py migrate
python manage.py createsuperuser                        # حساب ادمین
python manage.py runserver                              # http://127.0.0.1:8000

# ۲) فرانت (ترمینال دوم)
cd frontend
cp .env.example .env.local
npm install
npm run dev                                             # http://localhost:3000
```
- سایت: `http://localhost:3000` — پنل ادمین: `http://127.0.0.1:8000/admin/`
- بعد از اولین اجرا: `npm run typecheck` را بزنید و خطاها را رفع کنید، سپس دو خط `ignoreBuildErrors` و `ignoreDuringBuilds` را از `next.config.js` حذف کنید.

## گردش‌کار ادمین
1. **پرداخت‌ها** (`/admin/core/payment/`): فیلتر «در انتظار بررسی» ← رسید را ببینید ← ردیف را انتخاب کنید ← عملیات **«تأیید پرداخت و فعال‌سازی پرو»** (یا «رد رسید»). پیام خودکار در گفتگوی پشتیبانی کاربر ثبت می‌شود. تمدید به انتهای اشتراک فعلی اضافه می‌شود.
2. **پشتیبانی** (`/admin/core/supportthread/`): گفتگوی کاربر را باز کنید، در ردیف خالی انتهای صفحه متن را بنویسید و ذخیره کنید (هر پیام جدید از طرف پشتیبان ثبت می‌شود).
3. **کاربران** (`/admin/auth/user/`): ستون پلن + عملیات «فعال‌سازی پرو ۳۰ روزه / بازگشت به رایگان».

## معماری و امنیت
- Next همهٔ `/api/*` را به Django پروکسی می‌کند (rewrites) تا کوکی هم‌مبدأ بماند و CORS لازم نباشد.
- احراز هویت: توکن تصادفی (فقط **هش SHA-256** در دیتابیس) در کوکی `HttpOnly; SameSite=Lax; Secure` (در تولید).
- محافظ CSRF: هر درخواست تغییردهنده باید هدر `X-Requested-With: plannuma` داشته باشد (سایت‌های دیگر نمی‌توانند آن را بفرستند).
- محدودیت تلاش: ورود (۸ بار/۱۵ دقیقه)، ثبت‌نام، آپلود رسید، پیام پشتیبانی.
- رسیدها: اعتبارسنجی نوع واقعی فایل (magic bytes، فقط JPG/PNG/WEBP، ≤ ۵MB)، نام تصادفی، ذخیره در `private_media/` (عمومی نیست) و فقط برای staff در `/admin-files/receipt/<id>`.
- رمزها با هشِ پیش‌فرض Django؛ حداقل ۸ نویسه و رد رمزهای رایج/عددی.

## استقرار (خلاصه)
1. `DJANGO_DEBUG=0`، `DJANGO_SECRET_KEY` قوی، `DJANGO_ALLOWED_HOSTS`، `DJANGO_CSRF_TRUSTED_ORIGINS=https://دامنه`.
2. `python manage.py collectstatic` و اجرا با `gunicorn config.wsgi` (WhiteNoise فایل‌های استاتیک ادمین را سرو می‌کند).
3. Next: `npm run build && npm start` با `BACKEND_URL` درست. پیشنهاد: پشت nginx مسیرهای `/api`، `/admin`، `/admin-files`، `/static` را مستقیم به Django و بقیه را به Next بدهید (برای آپلود رسید هم مطمئن‌تر است). HTTPS الزامی است.
4. کش پیش‌فرض (LocMem) برای محدودیت تلاش فقط در یک پردازه کار می‌کند؛ با چند worker از Redis استفاده کنید (`CACHES`).
5. از `db.sqlite3` (یا Postgres) و پوشهٔ `private_media/` به‌طور منظم نسخهٔ پشتیبان بگیرید.

## هنوز ساخته نشده
قابلیت‌های اختصاصی پرو (قرار است بعداً توسعه یابند)، بازیابی رمز (چون ایمیل/موبایل نمی‌گیریم؛ فعلاً ادمین رمز را از پنل عوض می‌کند)، اعلان/یادآوری، تغییر رمز از داشبورد، حالت آفلاین (service worker) در نسخهٔ Next.
